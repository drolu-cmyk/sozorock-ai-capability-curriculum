# Learner submission guide

Submit evidence, not a polished story.

## Suggested folder

Use:

    portfolio/
      00-orientation/
      01-use-case/
      02-model-behavior/
      03-data-and-rag/
      04-workflows/
      05-agents/
      06-evaluation/
      07-ai-security/
      08-secure-design/
      09-governance/
      10-grc/
      11-capstone/
      12-defense/

## File naming

Use: module-id_artifact-name_v01_YYYY-MM-DD.ext

Example: M03_source-register_v01_2026-08-02.md

## Every submission should state

- learner name or approved identifier
- module and artifact
- date
- tool/model/version, if used
- source or data boundary
- what was tested
- result and limitation
- human review or approval boundary

## Remove before submission

- API keys and tokens
- personal identifiers
- client or employer confidential information
- protected health information
- private URLs
- unapproved screenshots

## Feedback request

Add one question for the trainer: “What is the next change that would make this evidence more trustworthy or useful?”
