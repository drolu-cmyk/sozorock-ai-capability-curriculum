# Learner BYOD setup

Bring your own device is supported. The curriculum should still work if a learner has limited bandwidth, no paid account, or no API access.

## Device

- Current browser
- Ability to create and save plain-text or Markdown files
- Screen reader, zoom, or other accessibility support as needed
- Optional code editor
- Optional terminal for the build path

## Account and data rules

- Use an approved workspace or a personal account with no sensitive data.
- Never paste credentials, private client material, protected health information, or personal identifiers into a lab.
- Use synthetic examples or public sources.
- Do not connect an AI tool to email, cloud drives, payment systems, production systems, or external actions unless the trainer has explicitly approved the lab and a human approval gate is present.

## Tool fallback

If an AI tool is unavailable:

- complete the same task manually;
- use the supplied mock examples;
- document the limitation;
- compare what changed when the tool became available.

## Before class

Test that you can open the repository, create a local evidence file, and save a copy outside the browser. Ask the trainer before class if you need an accessibility or connectivity accommodation.
