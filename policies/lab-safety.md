# Lab Safety and Data Handling

This policy applies to every learner, trainer, contributor, and lab environment.

## Data

1. Use synthetic, public, or de-identified data only.
2. Never commit API keys, passwords, tokens, certificates, private keys, or production logs.
3. Never upload protected health information, financial information, confidential client material, or personal information without documented authorization.
4. Minimize data. Use the least amount of information needed for the learning objective.
5. Delete temporary lab data when the exercise is complete.

## Systems and actions

1. Never test a system without authorization.
2. Do not connect a lab agent to email, payments, social media, production databases, or destructive tools.
3. Do not allow an AI system to send, delete, purchase, publish, or modify external records without human approval.
4. Use least privilege, explicit scopes, and reversible actions.
5. Record model, prompt, data, tool, and version assumptions.

## Evidence

1. Label AI-generated output as unverified until checked.
2. Preserve the test case, expected result, actual result, and reviewer decision.
3. Do not represent a model output as an authoritative source without verification.
4. Record limitations, residual risk, and the decision to proceed, redesign, or stop.

## Incidents

Report accidental exposure, unauthorized access, unsafe output, or suspected compromise immediately to the trainer or project steward. Stop the affected lab until it has been reviewed.

## Scope

This curriculum does not grant permission to attack, scan, scrape, access, or modify external systems. All cybersecurity exercises must use supplied targets or written authorization.
