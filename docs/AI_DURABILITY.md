# Staying useful as AI changes

The curriculum teaches durable capabilities rather than a list of product buttons.

## What stays durable

- Problem framing and user impact
- Data and source judgment
- Instruction and interaction design
- Workflow decomposition
- Evaluation and monitoring
- Threat modeling
- Access control and human oversight
- Risk, control, and evidence thinking
- Clear communication of uncertainty

## What changes

- Model names and versions
- Product interfaces
- Pricing and context limits
- Tool and API syntax
- Agent orchestration patterns
- Regulatory guidance and security techniques

## Design rules

- Every lesson has a tool-agnostic core task.
- Provider-specific steps are optional adapters.
- Learners record provider, model, version, date, and settings.
- Exercises can run with a mock or manual fallback.
- Examples are replaced when they no longer represent a current risk.
- Framework mappings are versioned and checked before release.

## Refresh cadence

- Monthly: scan for broken links, material tool changes, and lab-cost changes.
- Quarterly: review model behavior, AI security examples, and provider-neutral alternatives.
- Each release: check standards, legal references, licenses, accessibility, and learner feedback.
- Annually: retire or redesign lessons that are tool demonstrations rather than durable skills.

## The learner question

For every new AI trend, ask:

1. What capability does this make easier?
2. What new failure or threat does it introduce?
3. What evidence would show safe, useful performance?
4. What human decision must remain visible?
5. Can the learner repeat the lesson with another tool?
