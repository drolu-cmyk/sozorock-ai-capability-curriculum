# Cohort pilot plan

## Purpose

Validate that the curriculum can be delivered by a trainer and completed by learners using their own devices, without relying on a particular AI vendor.

## Pilot boundary

Pilot M00–M03 first. Do not advertise the full M00–M12 pathway until M04–M12 have passed the same pilot gate.

## Recommended pilot group

- One lead trainer
- One assistant or observer
- Two to six learners
- One approved workspace
- One shared issue log with no learner personal data

## Evidence to collect

- Time spent per activity
- Checkpoint completion rate
- Learner confidence before and after
- Artifact quality against the rubric
- Safety questions or incidents
- Tool failures and fallback behavior
- Trainer preparation time
- Accessibility barriers
- Which instructions required clarification

## Pilot decision rules

- Keep: delivered as written and produces the intended evidence.
- Revise: learners can complete it but instructions, timing, or examples cause friction.
- Hold: safety, privacy, assessment, or reproducibility is not acceptable.
- Retire: the task no longer represents a durable capability.

## Suggested schedule

| Session | Content | Evidence |
|---|---|---|
| 1 | M00 and M01 | agreement, baseline, use-case canvas |
| 2 | M02 | interaction test set and behavior report |
| 3 | M03 | source register and citation audit |
| 4 | Reflection | portfolio review and learner feedback |

## After the pilot

The trainer records a short delivery report, maintainers update the module status, and the changelog records material changes before public release.
